[[reference.upgrading]]
=== Upgrading to 2.0

This section lists the changes to make when you upgrade from a 1.5.x release to 2.0.
It applies to code that implements the model SPI: a custom `LlmService`, a `RoleResolver`, a factory that builds models from a user's key, or a source of locally served models.

These things do not change:

- **YAML configuration.** The keys under `embabel.models`, such as `default-llm`, `default-embedding-model`, `llms`, `roles`, `embedding-services` and `embedding-roles`, have the same names and the same meaning.
- **Calling code.** `Ai`, `PromptRunner`, `ModelProvider` and `EmbeddingService.embed` have the same methods. Code that only calls them compiles and behaves as before.
- **`CredentialEndpointResolver`.** A BYOK application that only registers `CredentialEndpointResolver` beans needs no change.

If your application uses none of the types in the table below, there is nothing to migrate.

==== What replaces each removed type

Chat and embedding used to have one set of SPI types each.
They now share generic types, and each generic type takes a `ModelKind` that says which kind of model it is for.
Use `LlmService.KIND` for chat models and `EmbeddingService.KIND` for embedding models.
A `RoleResolver` of `LlmService.KIND` is asked only about chat roles, and one of `EmbeddingService.KIND` only about embedding roles.

The "Shipped in" column is the first release that contained the removed type or method.

`RoleResolution.Credential` keeps its name and its constructor.
`ProviderCredential`, `ModelSelectionContext` and `ModelSelectionContextHolder` do not change.

===== Bean names in `embabel-agent-starter-byok`

The starter used to ship one factory bean per protocol and kind.
It now ships one `ModelPlatform` bean per protocol.
If your application replaced a shipped bean by registering a bean of the same name, rename your bean:

[cols="1,1",options="header"]
|===
|1.5.x bean name |Bean name now

|`anthropicCredentialLlmServiceFactory`
|`anthropicModelPlatform`

|`openAiCompatibleCredentialLlmServiceFactory`
|`openAiCompatibleModelPlatform`

|`openAiCompatibleCredentialEmbeddingServiceFactory`
|`openAiCompatibleModelPlatform`
|===

The OpenAI-compatible platform builds chat and embedding models.
A bean named `openAiCompatibleModelPlatform` therefore replaces both, so it must build every kind your application uses with OpenAI-compatible keys.
See <<reference.llms,Working with LLMs>> for the list of shipped platforms.

==== A custom streaming `LlmService`

In 1.5.x every `LlmService` declared `createMessageStreamer` and `supportsStreaming`, so a service that could not stream had to implement both anyway.
Now streaming is a separate interface, `StreamingChatCompletion`.

Before:

[source,kotlin]
----
data class MyCustomLlmService(
    // ... properties
) : LlmService<MyCustomLlmService> {

    override fun createMessageSender(options: LlmOptions): LlmMessageSender =
        MyCustomLlmMessageSender(httpClient, apiKey, options.model ?: name)

    override fun createMessageStreamer(options: LlmOptions): LlmMessageStreamer =
        MyCustomLlmMessageStreamer(httpClient, apiKey, options.model ?: name)

    override fun supportsStreaming(): Boolean = true

    // ... other methods
}
----

After:

[tabs]
====
Kotlin::
+
[source,kotlin]
----
data class MyCustomLlmService(
    // ... properties
) : LlmService<MyCustomLlmService>, StreamingChatCompletion {

    override fun createMessageSender(options: LlmOptions): LlmMessageSender =
        MyCustomLlmMessageSender(httpClient, apiKey, options.model ?: name)

    // Declared by StreamingChatCompletion now, not by LlmService.
    override fun createMessageStreamer(options: LlmOptions): LlmMessageStreamer =
        MyCustomLlmMessageStreamer(httpClient, apiKey, options.model ?: name)

    // supportsStreaming() is removed: it returns true because this class implements StreamingChatCompletion.

    // ... other methods
}
----

Java::
+
[source,java]
----
public class MyCustomLlmService implements LlmService<MyCustomLlmService>, StreamingChatCompletion {

    @Override
    public LlmMessageSender createMessageSender(LlmOptions options) {
        return new MyCustomLlmMessageSender(httpClient, apiKey, options.getModel() != null ? options.getModel() : name);
    }

    // Declared by StreamingChatCompletion now, not by LlmService.
    @Override
    public LlmMessageStreamer createMessageStreamer(LlmOptions options) {
        return new MyCustomLlmMessageStreamer(httpClient, apiKey, options.getModel() != null ? options.getModel() : name);
    }

    // supportsStreaming() is removed: it returns true because this class implements StreamingChatCompletion.

    // ... other methods
}
----
====

A service that does not stream deletes its `createMessageStreamer` and `supportsStreaming` methods and does not implement `StreamingChatCompletion`.
Keep a `supportsStreaming()` override only if it asks the provider whether the model streams.
An override that returns true on a class that does not implement `StreamingChatCompletion` has no effect: the platform reports that the model does not stream.

==== Role resolvers that return a user's key

`RoleResolver` is no longer a `fun interface`, because each resolver now states its kind.
Create one with `RoleResolver.of(kind) { role, context -> ... }`, or implement `RoleResolver<C, B>` and override `kind` and `resolve`.
The embedding resolver is the same type with `EmbeddingService.KIND`.

Before:

[source,kotlin]
----
@Component
class ByokRoleResolver(
    private val userKeyStore: UserKeyStore,
) : RoleResolver {

    override fun resolve(role: String, context: ModelSelectionContext): RoleResolution? =
        context.userId
            ?.let { userKeyStore.activeKeyFor(it) }
            ?.let { RoleResolution.Credential(ProviderCredential(it.provider, it.apiKey)) }
}

@Component
class ByokEmbeddingRoleResolver(
    private val userKeyStore: UserKeyStore,
) : EmbeddingRoleResolver {

    override fun resolve(role: String, context: ModelSelectionContext): EmbeddingRoleResolution? =
        context.userId
            ?.let { userKeyStore.activeKeyFor(it) }
            ?.let { EmbeddingRoleResolution.Credential(ProviderCredential(it.provider, it.apiKey)) }
}
----

After:

[tabs]
====
Kotlin::
+
[source,kotlin]
----
@Configuration
class ByokResolvers {

    // Chat roles: asked only about roles of LlmService.KIND.
    @Bean
    fun byokRoleResolver(userKeyStore: UserKeyStore): RoleResolver<LlmService<*>, LlmOptions> =
        RoleResolver.of(LlmService.KIND) { _, context -> credentialFor(userKeyStore, context) }

    // Embedding roles: asked only about roles of EmbeddingService.KIND.
    @Bean
    fun byokEmbeddingRoleResolver(userKeyStore: UserKeyStore): RoleResolver<EmbeddingService, ModelName> =
        RoleResolver.of(EmbeddingService.KIND) { _, context -> credentialFor(userKeyStore, context) }

    // One lookup for both kinds. RoleResolution.Credential is the same case for chat and embedding.
    private fun credentialFor(userKeyStore: UserKeyStore, context: ModelSelectionContext) =
        context.userId
            ?.let { userKeyStore.activeKeyFor(it) }
            ?.let { RoleResolution.Credential(ProviderCredential(it.provider, it.apiKey)) }
}
----

Java::
+
[source,java]
----
@Configuration
class ByokResolvers {

    // Chat roles: asked only about roles of LlmService.KIND.
    @Bean
    RoleResolver<LlmService<?>, LlmOptions> byokRoleResolver(UserKeyStore userKeyStore) {
        return RoleResolver.of(LlmService.KIND, (role, context) -> credentialFor(userKeyStore, context));
    }

    // Embedding roles: asked only about roles of EmbeddingService.KIND.
    @Bean
    RoleResolver<EmbeddingService, ModelName> byokEmbeddingRoleResolver(UserKeyStore userKeyStore) {
        return RoleResolver.of(EmbeddingService.KIND, (role, context) -> credentialFor(userKeyStore, context));
    }

    // Returns null when the user has no key, so the next resolver decides.
    private static RoleResolution.Credential credentialFor(UserKeyStore userKeyStore, ModelSelectionContext context) {
        if (context.getUserId() == null) {
            return null;
        }
        var key = userKeyStore.activeKeyFor(context.getUserId());
        return key == null ? null : new RoleResolution.Credential(new ProviderCredential(key.provider(), key.apiKey()));
    }
}
----
====

A resolver that returned `RoleResolution.Options(llmOptions)` now returns `RoleResolution.Bound(llmOptions)`.
An embedding resolver that returned `EmbeddingRoleResolution.Model("text-embedding-3-small")` now returns `RoleResolution.Bound(ModelName("text-embedding-3-small"))`.

Pass the kind's own constant, `LlmService.KIND` or `EmbeddingService.KIND`.
A kind equals only itself, so a resolver created with a new `ModelKind` of the same name is never asked, and the platform logs a warning about it at startup.

==== A credential factory becomes a `ModelPlatform`

A `ModelPlatform` replaces both `CredentialLlmServiceFactory` and `CredentialEmbeddingServiceFactory`.
Build one with `ModelPlatform.builder()` and call `builds(kind) { credential, model -> ... }` once for each kind it can build.
The function returns null for a provider it does not handle, as the factory did.

Before:

[source,kotlin]
----
@Bean
fun gatewayLlmServiceFactory() = CredentialLlmServiceFactory { credential, model ->
    if (credential.provider == "gateway") GatewayLlmService(credential.apiKey, model) else null
}

@Bean
fun gatewayEmbeddingServiceFactory() = CredentialEmbeddingServiceFactory { credential, model ->
    if (credential.provider == "gateway") GatewayEmbeddingService(credential.apiKey, model) else null
}
----

After:

[tabs]
====
Kotlin::
+
[source,kotlin]
----
@Bean
fun gatewayPlatform(): ModelPlatform =
    ModelPlatform.builder()
        // Each function returns null for any other provider, so other platforms handle those keys.
        .builds(LlmService.KIND) { credential, model ->
            if (credential.provider == "gateway") GatewayLlmService(credential.apiKey, model) else null
        }
        .builds(EmbeddingService.KIND) { credential, model ->
            if (credential.provider == "gateway") GatewayEmbeddingService(credential.apiKey, model) else null
        }
        .build()
----

Java::
+
[source,java]
----
@Bean
ModelPlatform gatewayPlatform() {
    return ModelPlatform.builder()
            // Each function returns null for any other provider, so other platforms handle those keys.
            .builds(LlmService.KIND, (credential, model) ->
                    credential.getProvider().equals("gateway") ? new GatewayLlmService(credential.getApiKey(), model) : null)
            .builds(EmbeddingService.KIND, (credential, model) ->
                    credential.getProvider().equals("gateway") ? new GatewayEmbeddingService(credential.getApiKey(), model) : null)
            .build();
}
----
====

A platform that builds only one kind calls `builds` once.
The platform caches each model per provider, key and model name, as it cached what a factory built.
For a provider that uses the OpenAI or Anthropic protocol, a `CredentialEndpointResolver` is still the simpler choice, because it needs no SPI type; see <<reference.llms,Working with LLMs>>.
