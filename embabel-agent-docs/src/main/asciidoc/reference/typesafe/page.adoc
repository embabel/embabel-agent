[[reference.typesafe]]
=== TypeSafe primitives (experimental)

TypeSafe is the provider; Jev is its decision model. Jev answers named questions about a shared state
using three primitives: `noul` for a truth value,
`choice` for a label with its distribution, and `score` for a value on an ordered rubric.
Embabel configures the native `TypeSafeClient` from `org.springaicommunity:typesafe-java-sdk:0.2.0`.
Requests, answers, model identity, usage and request identifiers remain SDK types.
This integration does not introduce a `DecisionModel`, a `ChatModel`, or a selection policy.

==== Relationship to Embabel model APIs

The native `TypeSafeClient` is a provider client, not an Embabel model abstraction, so this module
does not implement `ModelMetadata` or register the client with `ModelProvider`. A later model-layer
change can build on these primitives with a `DecisionModel` that participates in Embabel model
metadata and exposes classification through a narrower capability. Keeping that layer separate
lets applications use Jev now without making the provider SDK define the framework model contract.

==== Dependencies and Spring setup

Use `com.embabel.agent:embabel-agent-starter-typesafe` in a Spring Boot application.
The starter brings in `embabel-agent-typesafe-autoconfigure` and the core `embabel-agent-typesafe` module.
For plain Java, depend on `embabel-agent-typesafe` alone; it does not require the agent platform.

Adding the starter activates the integration. Supply `TYPESAFE_API_KEY` or set
`embabel.agent.platform.models.typesafe.api-key`.
A nonblank environment key takes precedence over the property, matching the other model providers,
and is resolved for each request so credential rotation takes effect on the next call.
Startup fails if neither supplies a key, unless an application-provided client replaces the default.
Other properties under `embabel.agent.platform.models.typesafe` are `base-url`
(default `https://api.typesafe.ai`), `model` (`jev-latest`), and `max-response-bytes` (`1048576`).
Inject the native `TypeSafeClient` into your application service or the constructor of an Embabel
agent, then call it from an action as you would any other service.

`TypeSafeProperties` lives in `com.embabel.agent.config.models.typesafe`.
The Boot entry point is `com.embabel.agent.autoconfigure.models.typesafe.AgentTypeSafeAutoConfiguration`,
registered through `AutoConfiguration.imports`. Its default bean is `typeSafeClient`.
These names identify the provider; changing the `model` property does not change the integration.

The base URI accepts HTTP(S) endpoints and proxy base paths. Use HTTPS for remote service calls.
Credentials, query parameters and fragments do not belong in the base URI.

An application-provided `TypeSafeClient` makes the default client configuration back off.

==== Transport, parsing and observations

The layers are:

[source,mermaid]
----
flowchart LR
    App[Application or action] --> Client[Native TypeSafeClient]
    Client --> Guard[Embabel guards around TypeSafeApi]
    Guard --> HTTP[Spring RestClient]
    HTTP --> TypeSafe[TypeSafe service]
----

`TypeSafeClients.create` accepts an optional `RestClient.Builder` and an `ObservationRegistry`.
For manual factory use, it clones the supplied builder, preserving its transport, interceptors,
proxy, TLS configuration and HTTP observation registry. The supplied `ObservationRegistry` controls
the logical TypeSafe observations and, when no builder is supplied, the fallback HTTP client.
Spring first selects the `aiModelRestClientBuilder` bean, then the only `RestClient.Builder` bean;
if neither is available it uses the fallback transport. When a unique application
`ObservationRegistry` bean is present, Spring clones the selected builder and attaches that registry
before creating the client. The shared builder remains unchanged.
The application owns that transport's timeouts and redirect policy. With Embabel's shared Netty
builder, use `embabel.agent.platform.http-client.connect-timeout` and
`embabel.agent.platform.http-client.read-timeout`.
There are no provider-specific timeout properties. The plain Java `TypeSafeClientOptions`
timeouts apply only to the fallback transport. Without a supplied builder, the fallback uses
10-second connect and read timeouts and does not follow redirects. Timeouts are not a hard end-to-end deadline.
Retries are fixed off with `RetryPolicy.noRetry()`.

TypeSafe decoding reads at most 1 MiB of each response by default. Supplied request factories or
interceptors may buffer or read the response before this bound applies; those components remain
application-owned. A private strict JSON mapper rejects duplicate fields and
trailing content; it does not inherit application Jackson modules.
`GuardedTypeSafeApi` owns this mapper because decoding is part of the provider's wire contract.
`EmbabelObjectMapperHolder` belongs to `embabel-agent-ai` and holds the platform's configured mapper;
using it here would add that dependency and make decoding depend on application customization.
The core TypeSafe module remains usable independently of the platform. Convert custom state into ordinary
JSON-compatible values in a `Map` or `JsonContent` before passing it to the SDK if application-specific
serialization is required. Do not mutate state, questions or nested collections during a call.

The logical `embabel.typesafe.request` observation opens a scope around each call.
Nested HTTP observations are children of the TypeSafe observation when both use the same registry.
Metrics and traces require the corresponding observation handlers and exporters on the registry;
the registry alone does not export them.
Embabel's own observation tags and log fields use bounded values and sanitized failures.
Application HTTP instrumentation, interceptors and status handlers have their own access to URLs,
headers and payloads; the application owns their instrumentation and redaction policy.
Avoid logging raw requests, responses or SDK exceptions.

Calls are synchronous. A caller or framework may invoke them from Java 21 virtual threads and owns
that thread's lifecycle.

Native SDK response objects are not a persistence or replay format. Map the fields you need into an
application-owned versioned record. The SDK's batch helpers, including `systemOneAll`, are unsupported
by this integration.

==== Experimental status

Promotion requires passing assembled Java and Spring integration tests for all three primitives,
model overrides, starter activation, custom-client backoff, credential precedence and rotation,
transport ownership, response bounds, strict parsing, sanitized failures, interruption and safe observations.
The published documentation and compiled examples must also pass the repository documentation build.
These criteria concern the primitive client integration; a later decision framework is a separate change.

The upstream source is https://github.com/spring-ai-community/spring-ai-typesafe/tree/v0.2.0[TypeSafe SDK 0.2.0].
