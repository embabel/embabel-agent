=== Typed Decisions

Typed decisions are experimental in this release. They give application code typed evidence and provenance while leaving every action, mutation, and persistence decision with the host. A `DecisionModel` is not an LLM, Spring AI `ChatModel`, agent role, or action executor. Automatic `Ai` or `ModelProvider` selection is deferred.

For explicit use, depend on `com.embabel.agent:embabel-agent-decision` and one provider leaf, normally `com.embabel.agent:embabel-agent-decision-typesafe`. Spring Boot applications can opt into `com.embabel.agent:embabel-agent-starter-decision`. The `embabel-agent-decisions` aggregate is Maven packaging only.

==== Invocation boundary

Every adapter enters the same facade. The facade validates the question schema, redacts state, captures one absolute deadline, validates raw evidence, and projects a policy-safe record. Providers cannot construct validated answers. A provider never chooses an application action.

==== Provider SPI

`DecisionProvider` is the public extension point for another decision engine. Custom implementations are extension adapters; they do not become additional built-in decision products. A provider receives one immutable, redacted `PreparedDecisionRequest` and returns raw evidence. It can be called concurrently, so its shared state must be thread-safe. It must not retain the request, state, questions, or support values after `invoke` returns.

The deadline is one absolute value from a monotonic process clock. It is not wall-clock time and must not be persisted or compared outside that request. Providers should use `remainingNanos()`, stop before it reaches zero, and honor thread interruption. The facade interrupts on cancellation or timeout and discards late results. An exception becomes `Unavailable`; caller interruption becomes `Cancelled`; an overrun becomes `DeadlineExceeded`.

Raw results have a deliberately narrow contract:

* A successful call carries provider provenance. Missing question answers become per-key `Missing` failures. Duplicate or unknown answer ids reject the complete call.
* A yes/no answer supplies finite `pTrue` in `0.0..1.0`. A selected id, when present, is `true` or `false` and must identify a maximizer.
* Choice and rating distributions contain every declared support id exactly once, contain no extra ids, use finite values in `0.0..1.0`, and sum to one within `1e-9`. A selected id is optional and must identify a maximizer. The facade resolves an omitted selection in declared order and preserves every maximizer.
* Call failures map canonically to `DISABLED`, `UNAVAILABLE`, `REJECTED_REQUEST`, `DEADLINE_EXCEEDED`, `CANCELLED`, or `UNSUPPORTED`. Key failures map to `MISSING`, `INVALID`, or `UNSUPPORTED`. The facade derives these safe codes from the failure enum and does not trust a provider-supplied code.

The facade owns final validation, request identifiers, question fingerprints, record projection, and typed application values. `DecisionOutcome` and `KeyOutcome` are sealed families with public `Success` and `Failure` variants, so Kotlin consumers can handle them exhaustively. A decision record is nullable only when record mode is `NONE`. An expected score is nullable for yes/no and choice outcomes and present for rating success.

==== Spring Boot configuration

Autoconfiguration is inert unless `embabel.agent.decision.enabled=true`. A user-provided `DecisionModel` wins before decision properties are validated. The created beans are named `decisionProperties` and `decisionModel`; `mapper-bean-name`, `prompted.llm-bean-name`, and `prompted.options-bean-name` select exact existing beans.

[cols="2,1,2"]
|===
|Property |Default |Meaning
|`embabel.agent.decision.enabled` |`false` |Opt into autoconfiguration
|`embabel.agent.decision.provider` |required |`typesafe`, `prompted`, or `none`
|`embabel.agent.decision.default-timeout` |`30s` |Positive facade default
|`embabel.agent.decision.record-mode` |`metadata` |`none`, `metadata`, or bounded `full`
|`embabel.agent.decision.full-record-max-bytes` |`65536` |Full-record byte ceiling
|`embabel.agent.decision.record-allowlist` |empty |Explicit full-record fields
|`embabel.agent.decision.mapper-bean-name` |unset |Exact `EmbabelObjectMapperHolder` bean
|`embabel.agent.decision.typesafe.model` |required for TypeSafe |Requested model; resolved identity comes from Jev
|`embabel.agent.decision.typesafe.base-url` |`https://api.typesafe.ai` |TypeSafe origin
|`embabel.agent.decision.typesafe.connect-timeout` |`10s` |Positive HTTP connect timeout
|`embabel.agent.decision.typesafe.api-key` |unset |Credential; `TYPESAFE_API_KEY` is the fallback
|`embabel.agent.decision.prompted.llm-bean-name` |required for prompted |Exact `LlmService` bean
|`embabel.agent.decision.prompted.options-bean-name` |unset |Exact `LlmOptions` bean; defaults when absent
|===

Spring selects `typesafe`, `prompted`, or `none`. `none` returns disabled outcomes. `StubDecisionModel` is test-only and deliberately absent from property selection.

==== Evidence, failure, and privacy

Yes/no yields a Boolean distribution. Choice and rating preserve declared support and every maximizer; rating also reports an expected ordinal score. Unknown or duplicate answer ids reject the call. Missing, invalid, and unsupported keys remain per-key failures so valid siblings survive. Call failures distinguish disabled, unavailable, rejected request, deadline, cancellation, and unsupported providers.

One monotonic deadline covers preparation, queueing, transport, and the single Jev retry allowed for an initial `429` or `529`. Late success is discarded. Caller interruption is restored.

Metadata records contain opaque identifiers, counts, schema versions, and safe codes. Facts, labels, application values, numeric evidence, free text, exception text, and credentials are excluded by default. Full records remain bounded and require an explicit allowlist. Redaction happens before transport. Provenance records only fields the provider actually supplied and the facade safely completed.

==== Running the examples

Each main intentionally calls the network. It refuses to call when `TYPESAFE_API_KEY` or `TYPESAFE_MODEL` is blank. Export both variables before running these commands. Run the first three commands from the repository root; the `cd` then moves into the leaf module for both launches.

[source,bash]
----
# Fail before Maven work if either live credential setting is absent.
: "${TYPESAFE_API_KEY:?export TYPESAFE_API_KEY before running the live examples}"
: "${TYPESAFE_MODEL:?export TYPESAFE_MODEL before running the live examples}"

# A standalone leaf classpath needs the current reactor BOM and artifacts installed first.
mvn -B -Dmaven.gitcommitid.skip=true -pl embabel-agent-dependencies install -DskipTests
mvn -B -Dmaven.gitcommitid.skip=true -pl embabel-agent-decisions/embabel-agent-decision-typesafe -am install -DskipTests
mvn -B -Dmaven.gitcommitid.skip=true -f embabel-agent-decisions/embabel-agent-decision-typesafe/pom.xml dependency:build-classpath -Dmdep.includeScope=test -Dmdep.outputFile=target/example-classpath.txt
cd embabel-agent-decisions/embabel-agent-decision-typesafe
java -cp "target/test-classes:target/classes:$(cat target/example-classpath.txt)" com.embabel.agent.decision.example.JevDecisionExampleKt
java -cp "target/test-classes:target/classes:$(cat target/example-classpath.txt)" com.embabel.agent.decision.example.JevDecisionExample
----

Windows uses `;` as the classpath separator; this release has not claimed a local Windows run. The live JUnit smoke fails closed unless the command supplies both the integration-profile marker and live opt-in:

[source,bash]
----
mvn -B -Pintegration-tests -Ddecision.live=true \
  -pl embabel-agent-decisions/embabel-agent-decision-typesafe -am \
  -Dtest=JevLiveSmokeIT -Dsurefire.failIfNoSpecifiedTests=false test
----

The `integration-tests` profile owns the authorization marker. Supplying the marker directly cannot enable the transport, so a direct `-Dtest=JevLiveSmokeIT` selection remains safe. The separate `decision.live=true` opt-in, a nonblank key and model are still required, and `CI` must be absent or exactly `false` (case-insensitive).

[[reference.decisions.promotion]]
==== Promotion checkpoint

Project maintainers own promotion in the release immediately after the first experimental release. The repository-observable checkpoint requires passing contract and validation suites, Java and Kotlin interoperability, adapter fixture compatibility, privacy, failure, deadline and cancellation tests, checked public API compatibility, current compiled consumer snippets, both executable consumer examples, an opt-in live provider smoke that records the resolved model, the generated guide and API documentation, and the full reactor verification. Every new public API and SPI remains `@ApiStatus.Experimental` in the first release. Maintainers will remove that marker in the next release once these gates pass; promotion does not wait for other engines, action calibration, or another release train.
