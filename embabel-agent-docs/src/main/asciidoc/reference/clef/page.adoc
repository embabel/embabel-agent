[[reference.clef]]
=== Experimental CLEF decisions

`com.embabel.agent:embabel-agent-starter-clef` adds optional CLEF auto-configuration and `embabel-agent-clef`.
The JVM module uses the shared SystemOne client and has no native dependency. Its factory is a `DecisionModelProvider`
with id `clef`, provider label `CLEF`, and one known model, `clef-text-0.6b-coreml`.
The default starter is disabled and performs no endpoint discovery, native loading or model downloading.
An application `ClefModelFactory` bean replaces its configured factory.

Enable `embabel.agent.platform.models.clef.enabled` and specify an explicit loopback HTTP `base-url`.
Other settings are `timeout` (default 45 seconds, positive and at most the shared client's 300 seconds),
`max-request-bytes` (default/max 16384), and `max-response-bytes` (default/max 65536).
Credentials, model/checker paths and a native process are not JVM properties.
Configure named services with the generic `decisions.services` provider/model properties shown in
xref:reference.decision-providers[Decision model providers]. A registry default or role selects those named services.

The linked pinned publisher artifact combines a Qwen backbone with a joint schema/probability head.
The native seam runs that decision head as well as the decoder; treating the checkpoint as ordinary chat serving would lose
that typed probability-head behavior. Generic PyTorch/MLX/vLLM serving support remains unverified.

==== Evidence and limits

One `ask` sends one joint set; requests are never split or truncated.
Propositions retain P(true) in `pTrue`, including false answers. Exactly 0.5 becomes the existing `Inconclusive` result,
which has no numeric field: that exact-half value cannot be retained through the current scalar proposition contract.
This API mapping is not native model abstention.
Choice results retain the reported confidence; their complete distribution is available on the ask response.
Scores retain an ordered complete level distribution, the probability-weighted zero-based expected level index,
and provider confidence. They have no selected level: rounding a score to a level would fabricate a categorical selection.
`DecisionProjection` therefore cannot project a score-only/distribution-only rating into a selected-level value.

The profile rejects oversized schemas before HTTP: state at most 4096 UTF-8 bytes; 1--16 questions;
nonblank instructions/descriptions or id fallbacks at most 512 UTF-8 bytes; 2--32 choices; 2--16 rating levels;
and at most 96 total head options, including two for each proposition. The shared serialized request cap is at most 16384 bytes.
Public Unicode/hostile category ids retain their original values and order; the native host maps them to opaque internal ids.
The L1024 tokenizer bucket imposes another bound: a full bucket is rejected because the publisher encoder can truncate state.
The JVM byte/schema checks do not guarantee token fit.

Operational outcomes are existing `UNAVAILABLE` or `INVALID_RESPONSE`; CLEF additionally maps native HTTP 502 to invalid response.
The host uses 400 for invalid request, 409 for busy, 503 for missing assets, 504 for native timeout, and 502 for invalid output.
The common client enforces a complete connect/header/body deadline, bounded responses, no retry or redirect, and unchecked
cancellation with the interrupt flag retained. Client cancellation does not prove remote checker cancellation;
the host separately bounds checker lifetime and shuts down child processes.

==== Explicit native provisioning and start

The host admits Apple-silicon macOS 15 or newer as its platform and Core ML API minimum.
The successful derived-bundle experiment was observed on macOS 27.0.1; this is not a load/support promise for every admitted host.
The operator-supplied checker also needs compatible macOS/Swift build settings. Python runtime tests use only the standard library and fake checkers;
import and `GET /health` do not load Core ML or verify hashes. Readiness is separate from successful inference.
The operator supplies an existing accepted derived bundle, its provenance JSON, a trusted checker and writable scratch directory.
The checker digest identifies supplied executable bytes; its pinned source revision and bounded build label are independently supplied.
Model weight equality does not attest runtime origin, native execution semantics, acceleration or calibration.

From the repository root, the shipped parser accepts this explicit command. Set the variables to external provisioned locations;
`CLEF_CHECKER_SHA256` must be the independently trusted 64-hex digest of that checker and `CLEF_CHECKER_BUILD_ID` a nonprivate label:

[source,shell]
----
python3 embabel-agent-clef/runtime/clef_server.py \
  --checker "$CLEF_CHECKER" --model-dir "$CLEF_MODEL_DIR" \
  --provenance "$CLEF_PROVENANCE" --scratch-dir "$CLEF_SCRATCH" \
  --checker-sha256 "$CLEF_CHECKER_SHA256" \
  --checker-source-revision 0230049c4e81f8de53ae1086b20cd9106c511105 \
  --checker-build-id "$CLEF_CHECKER_BUILD_ID" --port 8765
----

This foreground process exposes the owned SystemOne-compatible profile on loopback, including `/v1/systemone`, `/v1/models`,
and `/health`. It is started independently of the application. The older owned `/v1/decisions` route is not used by the JVM client.
The request remains one checker invocation, with one native inference in flight; concurrent losers receive busy.
The host verifies all seven pinned inputs and checker bytes before each inference and loads only a fresh per-request scratch bundle,
not preexisting compiled caches. Its default native deadline is 45 seconds; request socket timeout defaults to 5 seconds and
maximum connections to 16. Shutdown/cancellation reaps bounded native processes and does not retain a background worker.

The accepted experiment is derived from
https://huggingface.co/FluidInference/clef-text-0.6b-coreml/tree/3c61a60954478ef385aa42d67d5764642dcc9135[the Apache-2.0 publisher snapshot]
with source revision `3c61a60954478ef385aa42d67d5764642dcc9135`, using
https://github.com/FluidInference/FluidUse/tree/0230049c4e81f8de53ae1086b20cd9106c511105[the pinned FluidUse runtime].
The local variant is `local-single-function-L1024`, requested compute is CPU, and the attributed
`embabel-agent-clef/runtime/runtime.patch` adapts the checker to its single `main` function.
The original multifunction package failed to load in the observed experiment; the derived graph was compared semantically and
weight binaries were byte-identical. That is not a guarantee that the original package fails everywhere or that all runtime semantics match.

The diagnostic transformation selected L1024, copied its inputs/outputs, removed multifunction descriptions, renamed the graph to
`main`, and saved with coremltools 9.0 while preserving decoder/head weights. This was external provisioning, not a shipped installer.
Core ML serialization was not byte-stable across rebuilds. A source download and diagnostic rebuild therefore cannot promise
accepted byte-identical derived specs; regenerated provenance is not authority to replace the pins.
Public reproducibility of this exact derived bundle remains a limitation. No weights, compiled models, checkers or native build tools
are distributed with the JVM integration; source/license files and provenance must remain with the operator's external bundle.

The JVM profile requires exactly one bounded ASCII `X-Embabel-Clef-Provenance` JSON header with strict duplicate/trailing checks,
fixed model identity, experimental/protocol/source/license/variant/CPU/confidence semantics, all seven hashes and checker metadata.
Version records source revision, derived variant, CPU and checker digest. This is server-attested metadata; a self-reporting
loopback endpoint is not cryptographic remote attestation. It cannot establish calibration or engine correctness.
The published GPU/ANE performance numbers are publisher measurements; this derived experiment observed CPU placement.
It is not a ranking model, has no native abstention guarantee, and makes no universal PyTorch/MLX/vLLM or production-support claim.
