[[reference.decision-specs-annotated]]
=== Annotated records (prototype)

The module `embabel-agent-decision-annotations` reads a `DecisionSpec` from an annotated Java record or bean.
It is a prototype.
It is optional, it is not published, and no Embabel module depends on it.
The spec it reads is an ordinary `DecisionSpec`, equal to the spec the builder or the Kotlin DSL declares for the same questions.
The types are in the package `com.embabel.common.ai.decision.annotated` and carry `@ApiStatus.Experimental`.
The <<reference.decision-specs-annotated.evaluation>> section below holds the recommendation on keeping the module.

==== When to use annotations

An annotated record suits a decision whose answers the application reads back as one typed value.
The record declares the questions and receives the projected answers.

The builder and the Kotlin DSL suit a spec that is assembled at run time, a spec whose questions come from configuration or storage, and a spec that no Java type mirrors.
They also suit a question whose options are not a closed set known at compile time.

Both paths produce equal specs, so a process can declare a spec with annotations and another process can run it from JSON.

|===
|Annotation |Placed on |Declares

|`@PropositionQuestion(asking)`
|A `boolean` or `Boolean` property
|A proposition question

|`@ChoiceQuestion(asking)`
|A property of an enum type
|A choice question with one option per enum constant

|`@RatingQuestion(asking)`
|A property of an enum type
|A rating question with one level per enum constant

|`@Described(value)`
|An enum constant
|The description of an option or level
|===

The three question annotations target fields, methods and parameters.
On a record component, Java copies the annotation to the private field, the accessor and the canonical constructor parameter.
Jackson merges the accessor and the constructor parameter into one property, and the parser reads them as one question.
`asking` has no default and holds the instructions the model receives.
There is no class-level annotation.

Choices and rating levels are enums.
Options and levels follow the declaration order of the constants.
Rating levels run from lowest to highest.
Every choice constant needs `@Described`.
A rating constant without `@Described` takes its id as its description, as `RatingQuestionSpec.Builder.level(label)` does.

==== Names and order

Jackson supplies every name.
The question name is the Jackson property name of the annotated member.
The option or level id is the JSON string the mapper writes for the enum constant, and the parser checks that the mapper reads that string back as the same constant.
The question order is Jackson's property order for the type.

`@JsonProperty`, `@JsonNaming`, `@JsonPropertyOrder`, a mapper `PropertyNamingStrategy` and a mapper `EnumNamingStrategy` all change the spec.
Jackson 3 writes and reads enums with `toString()` by default, so an enum that overrides `toString()` takes its ids from it.
The name and the order are part of the spec, so a naming change produces a different spec.

An `AnnotatedDecisions` instance caches one `AnnotatedDecision` per type.

`AnnotatedDecision.questionNames()` maps each Java member name to its question name.

==== Projection

`AnnotatedDecision.project(response)` converts the answers of a response into the annotated type.
It first checks the response with `DecisionResponse.requireMatches(spec)` and throws `DecisionProjectionException` with that message when the check fails.
A response with missing, extra or reordered answers fails before conversion, and so does an answer whose kind, options or levels differ from its question.
Instructions are not compared, so a response to reworded questions still projects.
The conversion is `DecisionProjection.of(response, type, mapper)` with the mapper that read the type.
Inconclusive, failed and unmatched answers, and ratings answered with only a score, throw the same `DecisionProjectionException` as in <<reference.decision-specs>>.
The result holds the converted value and the response, so the provenance of each answer stays available.

A type can hold properties that carry no question annotation, such as identity fields.
`project(response, otherProperties)` takes their values from a map keyed by Jackson property name.
Every such property needs a key, and a key that names a question or no property is rejected.
The message lists every key problem at once.

Projection has these limits:

* `AnnotatedDecisions.of` takes a `Class<T>`. A property whose type is a type variable is rejected when the type is read. A generic target type such as a map uses `DecisionProjection.of` with a `TypeReference<T>`.
* `project(response, otherProperties)` returns `T`. The core `DecisionProjection` holds only values converted from answers, and its constructor is private, so it cannot hold values from `otherProperties`. The caller keeps the response for provenance.
* A record component with `@JsonIgnore` stays a creator parameter in Jackson. The default mapper enables `FAIL_ON_MISSING_CREATOR_PROPERTIES`, so projection fails on the ignored component. Under a mapper without that feature the component projects as `null`. The ignored component is not an `otherProperties` key in either case.

==== Errors

A type that cannot become a spec throws `AnnotatedDecisionException`, an `IllegalArgumentException`.
The parser collects every problem in the type and reports them in one exception.
`problems()` returns one line per problem, in the form `<Type>.<member>: <cause>. <fix>.`
A problem that concerns the whole type starts with `<Type>:`.
A Jackson or builder exception behind a problem is the cause of the exception, and further ones are suppressed exceptions.
A failed read is not cached.

|===
|Situation |Message form |Fix

|No question annotation in the type
|`<Type>: declares no questions.`
|Annotate at least one property

|Wrong property type
|`<Type>.<member>: @ChoiceQuestion needs an enum type, found java.lang.String.`
|Declare a `boolean` for a proposition, an enum for a choice or rating

|Type variable property
|`<Type>.<member>: @ChoiceQuestion needs a concrete enum type, found type variable E, which Jackson reads as java.lang.Enum.`
|Declare a concrete enum type

|Two question annotations on one property
|`<Type>.<member>: carries @PropositionQuestion and @ChoiceQuestion.`
|Keep one question annotation

|Different `asking` values on members of one property
|`<Type>.<member>: members of the property carry @PropositionQuestion with different asking values (...).`
|Use one `asking` value

|Blank `asking`
|`<Type>.<member>: @PropositionQuestion has a blank asking value.`
|Set the instructions

|Choice constant without `@Described`
|`<Type>.<member>: choice option <Enum>.<CONSTANT> has no @Described.`
|Add `@Described`

|Choice enum without constants, rating enum with fewer than two
|`<Type>.<member>: <Enum> has 1 constant, and a rating needs at least two levels.`
|Add constants

|Enum written as a number
|`<Type>.<member>: <Enum>.<CONSTANT> serializes as 0 under this mapper, and an option id must be a JSON string.`
|Write enums as strings

|Enum id that reads back as another constant, or does not read back
|`<Type>.<member>: option id "..." of <Enum>.<CONSTANT> reads back as <Enum>.<OTHER> under this mapper.`
|Give each constant a distinct serialized form

|Question on an ignored property
|`<Type>.<member>: carries @PropositionQuestion but Jackson ignores the property (...).`
|Remove the annotation or stop ignoring the property

|Question on a member outside any property
|`<Type>.<member>: carries @PropositionQuestion but is not a Jackson property.`
|Move the annotation to a record component, field, getter or creator parameter

|Question on a field or method that Jackson leaves out of a property of the same name
|`<Type>.<member>: carries @PropositionQuestion but Jackson leaves this field out of the property "urgent".`
|Move the annotation to one of the members the message lists

|Question property without a creator parameter, setter or field
|`<Type>.<member>: carries @PropositionQuestion but Jackson has no creator parameter, setter or field to set it.`
|Add one of these members

|Members with different Java names merged into one property
|`<Type>.<member>: Jackson merges flag and isHot() into the property "urgent".`
|Rename the members to one Java name, or give each its own property name

|Two members Jackson cannot merge
|`<Type>: Jackson cannot read the properties of the type (...).`
|Give each member its own property name

|Response to another spec
|`Response answers spec s1-... but <Type> reads spec s1-....`
|Ask with `AnnotatedDecision.spec()` for this type and mapper

|Missing `otherProperties` key
|`<Type> needs values for [sourceRevision].`
|Pass the keys in `otherProperties`
|===

The last two rows throw `DecisionProjectionException` from projection.
The others throw `AnnotatedDecisionException` when the type is read.

==== Kotlin

The question annotations have no Kotlin `PROPERTY` target, so a use-site target decides which Java member carries them.
The table records the placements on a `data class` constructor `val`, read with `jackson-module-kotlin` 3.1 and Kotlin 2.2.

|===
|Placement |Member Kotlin annotates |Result

|No use-site target
|Constructor parameter, and the matching parameter of `copy()`
|Reads. The spec equals the Java record's.

|`@param:`
|Constructor parameter, and the matching parameter of `copy()`
|Reads. The spec equals the Java record's.

|`@get:`
|Getter
|Reads. The spec equals the Java record's.

|`@field:`
|Private backing field
|Rejected. Jackson leaves a private field out of a property that a creator parameter sets. The message names the constructor parameter and the getter.

|`@param:` and `@field:` together
|Constructor parameter, `copy()` parameter and private backing field
|Reads. The parser skips the field because it carries the same question annotations as the constructor parameter.

|`@property:`
|None
|Does not compile.
|===

The parser skips a `copy()` parameter that carries the same question annotations as the constructor parameter.
The `componentN()` methods carry no annotations.
A plain `class` has no `copy()`, and the default site reads there too.
An annotation on a Kotlin enum entry, such as `@Described`, sets the option or level description.

The annotated declaration is 18 non-blank lines and the builder call is 13.
The annotated declaration also defines the projection target and the enums the application reads.
With the builder, a typed projection needs the same record and enums in addition to the builder call.
The option and level ids exist once, as enum constants, so a renamed constant changes the spec and the projection together.
Question names and ids come from the application's Jackson settings, so the spec follows the JSON conventions the application already uses.

The costs to a user are the rules a Java type must satisfy: a `boolean` or enum per question, `@Described` on each choice constant, and a Kotlin use-site target that reads.
Each rule has a diagnostic that names the member and the fix.

===== Complexity

The main code is 1,489 lines in nine Java files, 932 of them non-blank and outside comments.
`DecisionTypeParser` holds 881 of the lines.
`AnnotatedDecision` holds 200, `AnnotatedDecisions` 110, `AnnotatedDecisionException` 73, and the four annotations and `package-info` 223 together.
The tests are 2,426 lines, most of them diagnostic cases.

The parser reads Jackson's creation view of a type through public calls: `DeserializationConfig.classIntrospectorInstance()`, `ClassIntrospector.introspectForCreation`, `BeanDescription.findProperties()`, `AccessorNamingStrategy` and `AnnotationIntrospector`.
These calls are public and lower level than `ObjectMapper`.
A Jackson minor release that changes introspection can change what the parser reports.
Part of the parser code locates annotations that Jackson does not attach to any property, which Jackson offers no call for.
The Kotlin data class rule reads the `kotlin.Metadata` annotation by name, so the module has no Kotlin dependency.

===== Supported types

* Question properties: `boolean` or `Boolean` for propositions, a concrete enum for choices and ratings. Every other type is rejected.
* Types: Java records, beans with a `@JsonCreator` constructor or setters, and Kotlin classes with the placements in the Kotlin table.
* Reading: `Class<T>`. Generic types and type variables are rejected.
* Projection into `T` with `DecisionProjection<T>` when every property is a question, and into `T` alone when `otherProperties` supplies the rest.
* `@JsonIgnore` on a record component: the component cannot hold a question and fails projection under the default mapper.

===== Costs

* The merged-name check is strict. A property whose field, getter and setter have different Java names is rejected even where Jackson accepts it, for example `@JsonProperty("urgent") boolean urgentFlag` with `isUrgent()`. Creator parameters are left out of the check.
* The parser depends on the Jackson introspection calls listed under Complexity. A Jackson upgrade needs the module tests to pass before release.
* `project(response, otherProperties)` returns `T` alone. A public factory on `DecisionProjection` that takes a value would let it return `DecisionProjection<T>`. That change belongs to `embabel-agent-ai`.
* `defaults()` holds one shared mapper. Jackson's type and deserializer caches in that mapper keep references to the types it reads and projects, so an application that reloads classes passes a mapper it owns to `using(mapper)`. The decision cache itself keeps no class reachable.
* Kotlin support depends on use-site targets and on two rules that skip Kotlin's repeated annotations: one for `copy()` parameters and one for the backing field.

===== Removal

Removing the module is `git rm -r embabel-agent-common/embabel-agent-decision-annotations`, the deletion of this file, and the removal of one `<module>` line and one `include::` line.
No other module refers to it.
With the module and its `<module>` line removed, `embabel-agent-ai` and the modules it depends on compile.

===== Recommendation

Retain the module as an opt-in prototype after revision, and keep it unpublished until this recommendation is accepted.
The annotated path produces specs equal to the builder's, projects into the declaring type after checking the response against the spec, and reports every problem with its member and fix.
The conditions for accepting it are:

. Exclude the module from Maven Central publication and confirm the exclusion in a release dry run. The module sets `maven.deploy.skip`.
. Review the Jackson introspection calls against the Jackson version the release uses.
. Add a public factory to `DecisionProjection` so that `project(response, otherProperties)` returns `DecisionProjection<T>`.
. Name an owner and a consumer application, as the decision types require for promotion.

Drop the module if no consumer application adopts it by the release that promotes the decision types.
